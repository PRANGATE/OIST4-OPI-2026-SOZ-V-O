# Процесс разработки

## Проект

«Дневник сна» (Sleep Diary), вариант 25. Приложение реализовано на HTML, CSS и JavaScript без серверной части. Записи и настройки сохраняются в localStorage браузера.

## Рабочий процесс Git

1. Для каждой отдельной функции создаётся ветка от main с префиксом feature/.
2. Изменения фиксируются небольшими коммитами с Conventional Commits (feat:, fix:, style:, docs:, ci:).
3. После реализации создаётся Pull Request в main.
4. В описании PR указывается выполненная работа, проверки и ссылка на Issue через Closes #N.
5. Перед слиянием проводится self-review во вкладке Files changed; замечания фиксируются в Review.
6. После проверки PR объединяется в main. Для отдельных функциональных веток допускается Squash and merge.

## Автоматическая проверка

Workflow `.github/workflows/ci.yml` запускается при push в main и при Pull Request в main. Он проверяет наличие основных файлов, ключевые элементы HTML, синтаксис JavaScript через `node --check` и ошибки пробелов через `git diff --check`.

## Локальный запуск

Откройте `index.html` в современном браузере. Для проверки сохранения создайте запись, перезагрузите страницу и убедитесь, что запись осталась. Для проверки перехода через полночь задайте, например, 23:00 и 07:00: ожидаемая длительность — 8 часов.

## Ограничения текущей версии

- Данные хранятся только в браузере и не синхронизируются между устройствами.
- Очистка данных сайта в браузере удалит локальные записи.
- Автоматические уведомления о времени сна, экспорт CSV и расширенные сценарии тестирования требуют отдельной реализации.
